# Прайсинг опционов

Расчёт цены европейских и американских опционов тремя моделями
(Блэк-Шоулз, биномиальное дерево CRR, Монте-Карло) с последующим расчётом
греков. Рыночные данные — yfinance, хранение — PostgreSQL, API — FastAPI,
интерфейс — статическая HTML-страница.

## Быстрый запуск

Нужен только Docker:

```bash
docker compose up
```

Дальше http://localhost:8000 — страница, и http://localhost:8000/docs —
документация API.

Поднимется PostgreSQL, создастся база, накатятся миграции и запустится
приложение. Ни Python, ни PostgreSQL ставить не надо, `.env` не нужен.

Первый запуск дольше: собирается образ, а потом приложение опрашивает
скринер Yahoo и проверяет по каждой бумаге, торгуются ли по ней опционы —
это десятки сетевых запросов. Дальше данные берутся из кэша.

Нужен интернет: рыночные данные тянутся с Yahoo вживую. Источник
неофициальный, и если он в этот момент недоступен или упёрся в свои
лимиты, список бумаг придёт пустым — это не поломка проекта. Кнопка
«Синхронизировать» на странице повторяет попытку.

Остановить — `Ctrl+C`. Убрать вместе с данными — `docker compose down -v`.

## Запуск без Docker

Нужны Python 3.12 и PostgreSQL.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # и вписать пароль от своего PostgreSQL

psql -U postgres -h localhost -d postgres -f sql/00_init_db.sql
alembic upgrade head

uvicorn app.main:app --reload
```

Без PostgreSQL приложение тоже поднимется, но пользоваться им не выйдет:
список бумаг останется пустым, а синхронизация вернёт ошибку — хранить
справочник негде.

## Настройка

Пароль к БД и прочие параметры — в `.env` (см. `.env.example`).
При запуске через Docker всё нужное задано в `compose.yml`.

Схема базы — миграциями Alembic:
```bash
alembic upgrade head            # привести базу к текущей схеме
alembic revision --autogenerate -m "что поменяли"   # после правки app/db/entities.py
alembic downgrade -1            # откатить последнюю миграцию
alembic current                 # на какой версии база сейчас
```
Строка подключения берётся из `.env`, в `alembic.ini` её нет — чтобы пароль
не попадал в репозиторий.

## Тесты

```bash
pytest
```

Работают без настройки: сеть подменяется, математика базы не знает.
Пять тестов смотрят в таблицы напрямую — без PostgreSQL они
пропускаются с объяснением, остальные идут как идут.

Если PostgreSQL поднят, тесты заводят себе отдельную базу
`pricing_test` и пишут только в неё: боевая `pricing` при прогоне не
меняется.

## Ограничения нагрузки

| что | настройка | по умолчанию |
|---|---|---|
| запросов с адреса на всё | `RATE_LIMIT` | 120/мин |
| запросов на расчёты | `PRICING_RATE_LIMIT` | 30/мин |
| расчётов одновременно | `MAX_CONCURRENT_PRICING` | 4 |

Первые два — частота (slowapi), третий — потолок памяти: Монте-Карло на
пяти миллионах путей занимает 200 МБ, и без ограничения сорок таких
расчётов разом съели бы восемь гигабайт. Превышение частоты — ответ 429.

## Служебные команды

Заменить справочник бумаг целиком (удаляет то, чего нет в новом ответе
скринера, вместе с их рыночными снимками):
```bash
python -m scripts.sync_instruments --replace
```
Через HTTP это сделать нельзя намеренно: `POST /api/instruments/sync`
только дополняет и освежает, и требует заголовок `X-Admin-Token`.
Страница подставляет его сама, для скриптов задайте `ADMIN_TOKEN` в
`.env`.

## Командная строка

Внизу страницы строка ввода — она дёргает те же расчёты, что и кнопки:

```
use AAPL                       выбрать бумагу
price 340 2026-10-16 call      посчитать
price --model mc --sigma 24.5  та же цена, другой моделью и σ
compare                        все три модели сразу
vol                            историческая, GARCH, EGARCH
smile · greeks · conv · parity открыть соответствующую закладку
help                           список команд
```

Аргументы необязательны: без них команда берёт то, что уже в форме.
История — на стрелках вверх и вниз.
