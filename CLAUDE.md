# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команды

```bash
source .venv/bin/activate
uvicorn app.main:app --reload      # http://127.0.0.1:8000, /docs — Swagger

alembic upgrade head                                # накатить схему
alembic revision --autogenerate -m "что поменяли"   # после правки app/db/entities.py
alembic downgrade -1
alembic current

pytest                                       # 693 теста, около четырёх секунд
pytest tests/test_parity.py -q               # один файл
pytest -k "паритет or dividend" -q           # по имени
```

Тесты бегают быстро потому, что ни один не поднимает сервер и не ходит в
базу: сеть подменяется через `monkeypatch`, а `app/pricing/` вызывается
напрямую. Если новый тест требует живого источника — почти наверняка
проверяемый код оказался не в том слое.

База создаётся один раз вручную: `psql -U postgres -h localhost -d postgres
-f sql/00_init_db.sql`. Строка подключения берётся из `.env` (см.
`.env.example`), в `alembic.ini` поле `sqlalchemy.url` намеренно пустое —
его подставляет `alembic/env.py` из настроек.

Линтера и форматтера в проекте нет.

## Архитектура

Поток одного расчёта: `static/app.js` → `routers/pricing.py` →
`services/pricing_service.py` → `pricing/<модель>.py` → обратно тот же
ответ пишется через `db/repository.py`.

Слои разделены жёстко, и это главное ограничение проекта:

- **`app/pricing/`** — чистая математика. Импортирует только numpy/scipy и
  собственные модули. Не знает ни про FastAPI, ни про БД, ни про
  yfinance; отлаживается из консоли отдельно от браузера. Любая модель
  принимает `OptionParams` и возвращает `PricingResult` — этот контракт
  задаёт `pricing/models.py`. Под контракт не подпадают `bounds.py`,
  `numeric_greeks.py`, `implied_vol.py` и `parity.py`: они не считают
  цену, а проверяют её или решают обратную задачу.
- **`app/services/market_data.py`** — единственное место, где живут
  `yfinance` и `pandas`. Наружу отдаёт только Pydantic-схемы; DataFrame
  за границы модуля не выходит. Смена провайдера данных должна
  затрагивать только этот файл.
- **`app/services/pricing_service.py`** — единственная точка, где
  встречаются HTTP-схемы и математика: считает T, собирает
  `OptionParams`, диспатчит по `PricingModel`.
- **`app/db/`** — SQLAlchemy async. Репозиторий отделён от
  `pricing_service` намеренно: расчёт не зависит от доступности базы.
- **`app/static/`** — ванильный JS без сборки, четыре файла плюс
  `vendor/plotly-basic.min.js`. Plotly положен в репозиторий, а не тянется
  с CDN: страница должна открываться без интернета. Свои графики руками
  на SVG не рисовать — все строятся через `Plotly.newPlot`.

  Страница — терминальный дашборд в две колонки: слева ввод (липкая
  колонка), справа результат и пять закладок. `command.js` загружается
  после `app.js` и вызывает его функции напрямую — сборки нет, оба файла в
  одной области видимости. Своих запросов к API в `command.js` нет ни
  одного: команда заполняет те же поля и нажимает те же кнопки, что и
  мышь, поэтому проверки ввода и обработка ошибок ей достаются, а не
  дублируются.

### Соглашения, которые легко нарушить

- **Ставки и волатильность везде — доли единицы** (0.0412, не 4.12).
  Перевод из процентов делает фронт, бэкенд получает уже доли.
- **252 против 365 — разница намеренная.** Волатильность приводится к
  году через торговые дни (`TRADING_DAYS = 252` в `market_data.py`),
  срок до экспирации и дисконтирование — через календарные
  (`DAYS_IN_YEAR = 365.0`). Деньги дисконтируются каждый день, цена в
  выходные не меняется.
- **Греки возвращаются в терминальных единицах, а не как сырые
  производные:** vega и rho — на процентный пункт, theta — на
  календарный день. Пересчёт делает каждая модель у себя, см. докстроку
  `Greeks`.
- **T считает сервер** из даты экспирации, форма его не передаёт: браузер
  может стоять в другом часовом поясе.
- **Валидация продублирована** в `schemas/pricing.py` и в
  `OptionParams.__post_init__` — это не дублирование по недосмотру: схема
  объясняет опечатку пользователю на границе HTTP, датакласс защищает
  библиотеку, которую можно вызвать мимо API.
- **`GET /{ticker}/market` — обычный `def`, не `async`**: yfinance ходит в
  сеть синхронно и заблокировал бы event loop. `POST /price` наоборот
  `async`, но сам расчёт уходит в `run_in_threadpool` — дерево и
  Монте-Карло упираются в процессор на сотни миллисекунд.
- **Ошибка записи в историю не должна отнимать посчитанную цену**:
  исключение логируется, ответ уходит с `calculation_id = null`.
- **`history(auto_adjust=True)`** принципиален: без него сплиты и
  дивидендные отсечки завышают историческую волатильность.

### Состояние работ

Проект доделан, TODO в коде не осталось. Что он умеет — в `README.md`.

Работающая цепочка: выбор бумаги из списка со скринера Yahoo → рыночные
данные с кэшем → форма параметров → три модели с греками → сравнение всех
трёх → история в PostgreSQL → цепочка опционов с подразумеваемой
волатильностью → улыбка → графики сходимости → сверка входных данных с
рынком по паритету колла и пута.

Эндпоинты: `POST /api/price`, `/price/compare`, `/price/convergence`,
`/price/profiles`, `GET /api/instruments` (+ `/sync`, `/{ticker}/market`,
`/{ticker}/chain`, `/{ticker}/parity`, `/{ticker}/quote`).

Замена справочника целиком — не эндпоинт, а команда:
`python -m scripts.sync_instruments --replace`.

Отложено сознательно, строить впрок не нужно:

- **ARCH/GARCH** — заявленное направление владельца проекта на будущее.
  Озвученные им планы это контекст, а не задача: полей и кода под них
  заранее не добавлять.
- **Longstaff-Schwartz** (американский Монте-Карло) — обсуждался и
  отвергнут: дерево ту же задачу решает быстрее и точнее.

### Что легко сломать по незнанию

- **Профили греков считаются моделью по стилю, а не выбранной
  пользователем.** Для европейского — Блэк-Шоулз: он даёт точное
  значение, к которому дерево и Монте-Карло лишь сходятся, и считать
  кривую приближённо было бы и медленнее, и хуже. Для американского —
  дерево на 200 шагах и 60 точках вместо 120 (500 шагов дали бы 825 мс на
  одну кривую вместо 267). Монте-Карло не годится вовсе: шестьдесят точек
  по двенадцать симуляций — десятки секунд, и кривая вышла бы дёрганой от
  случайного шума.
- **Вега по волатильности графиком не строится намеренно.** У опциона на
  деньгах вега от σ почти не зависит: 0.379 при 10% против 0.388 при 80%.
  График вышел бы горизонтальной прямой, и первая мысль была бы
  «сломалось». Содержательна вега по цене актива — колоколом, как гамма.
- **Рыночная цена контракта — отдельный эндпоинт, не часть `/price`.**
  Цепочка тянется из сети около 360 мс, расчёт занимает единицы
  миллисекунд; страница запрашивает то и другое параллельно. Цена
  последней сделки не показывается: сделка могла быть неделю назад при
  другой цене актива — по той же причине и волатильность считается от
  середины спреда.
- **Цвета графиков — тёмный столбец проверенной палитры, а не
  перекрашенный светлый.** Слот 1 `#3987e5`, слот 2 `#d95926`, поверхность
  `#1a1a19`, линейки `#383835`. Для тёмной поверхности ступени подобраны
  отдельно, автоматический переворот светлых их бы испортил. Состояния
  (`--good`, `--warning`, `--error`) взяты из отдельного набора и никогда
  не используются как ещё один ряд данных.
- **Видимостью пяти панелей управляет только `showTab`.** Раньше каждая
  карточка прятала и показывала себя сама; с закладками это спорило бы с
  переключателем. Не возвращать `card.hidden = false` в обработчики.
- **После открытия закладки нужен `Plotly.Plots.resize`.** График,
  нарисованный в скрытом элементе, получает нулевую ширину и схлопывается
  в полоску; починить можно только когда элемент стал видимым. По той же
  причине команды `smile`, `greeks`, `conv` открывают свою закладку до
  запроса, а не после.
- **Нагрузка ограничена двумя разными вещами, и обе нужны.** Частота —
  slowapi, `RATE_LIMIT` на всё и `PRICING_RATE_LIMIT` на расчёты.
  Одновременность — семафор `limits.pricing_slot()`, которым обёрнут
  каждый `run_in_threadpool` в `routers/pricing.py`. Лимит частоты не
  держит память: «тридцать в минуту» не мешает всем тридцати прийти в
  одну секунду, а `monte_carlo.calculate` на пяти миллионах путей занимает
  200 МБ и 389 мс — симуляция гоняется двенадцать раз, одна на цену и
  одиннадцать на численные греки. Без семафора сорок потоков FastAPI дали
  бы восемь гигабайт пика. Семафор, в свою очередь, не отказывает, а
  ставит в очередь, и без лимита частоты очередь росла бы без предела.
- **Семафор создаётся по событийному циклу, а не один на модуль.**
  `asyncio.Semaphore` привязывается к первому же циклу, который его
  тронул, и в любом другом падает с «bound to a different event loop».
  Uvicorn держит один цикл, поэтому в бою это всплыло бы не сразу — зато
  сразу на всех расчётах.
- **В тестах лимитер выключен** автоматической фикстурой `rate_limits_off`
  в `conftest.py`, иначе набор упирался бы в собственную защиту:
  расчётных запросов за прогон около тридцати. Проверки самого лимитера
  включают его обратно через фикстуру `rate_limits_on`.
- **`POST /api/instruments/sync` требует заголовок `X-Admin-Token`.**
  Сервер слушает localhost, но послать на него POST может любая страница,
  открытая в браузере пользователя: у «простого запроса» предварительной
  проверки CORS нет. Токен берётся из `ADMIN_TOKEN`, иначе генерируется
  при старте; страница получает его мета-тегом, который подставляет
  `main.index`. Заголовков CORS приложение не отдаёт вовсе — на этом
  держится защита, не включать их бездумно. Подробности в
  `app/security.py`.
- **Удаления бумаг через HTTP нет и быть не должно.** `replace` из
  эндпоинта убран после того, как
  `POST /api/instruments/sync?count=1&replace=true` оказался способен
  почти обнулить справочник, а вместе с ним каскадом и `market_snapshots`
  по внешнему ключу `ON DELETE CASCADE`. Параметр остался в
  `repository.sync_instruments` и доступен только из командной строки, с
  показом списка на удаление и подтверждением.
- **История расчётов наружу не отдаётся.** Каждый расчёт пишется в
  `calculations`, но ни эндпоинта, ни блока на странице для неё нет:
  смотрят её прямо в PostgreSQL. Записи старше
  `CALCULATION_RETENTION_DAYS` (по умолчанию три дня) удаляет фоновая
  задача в `main.py` — при старте и дальше раз в час.
- **Тесты идут в свою базу `<основная>_test`.** Фикстура
  `use_test_database` в `conftest.py` — автоматическая и на всю сессию
  именно поэтому: когда подмена включалась по требованию, полсотни
  тестов до первого её запросившего успевали записать историю в боевую
  базу. База и таблицы создаются сами (`Base.metadata`, не Alembic:
  тесту нужна схема, а не её история), таблицы чистятся перед прогоном —
  чтобы после упавшего теста содержимое осталось для разбора.
- **Без PostgreSQL `pytest` обязан быть зелёным.** Пять тестов, которые
  смотрят в таблицы напрямую, берут фикстуру `database` и пропускаются с
  объяснением; остальные шестьсот сорок два идут как шли. Тот, кто
  впервые склонировал репозиторий, запускает `pytest` раньше, чем читает
  README.
- **Движок тестовой базы — с `NullPool`.** У каждого `TestClient` свой
  событийный цикл, а пул привязывает соединения к тому, в котором их
  открыл: с обычным пулом второй клиент падает на «attached to a
  different loop».
- **`URL.render_as_string(hide_password=False)`, а не `str(url)`.**
  `str()` подставляет вместо пароля «***», и подключиться такой строкой
  нельзя.
- **`purge_old_calculations(retention_days=0)` в тестах не вызывать.**
  Это «удалить всё старше сего момента», то есть снести таблицу целиком.
  Один раз уже снесло — тогда тесты ещё ходили в боевую базу.
- **Ни одного тикера в коде не зашито.** Список приходит из скринера
  Yahoo в таблицу `instruments`; на пустой базе `main.py` тянет его сам
  при старте. Хардкод списка бумаг — прямое нарушение требования.
- **`div_yield` — не трейлинговая доходность.** Считается под конкретную
  экспирацию по датам дивидендных отсечек: до ближайшей отсечки q равно
  нулю, внутрь срока попала — q скачком вырастает. Поле `div_yield` в
  снимке это старая трейлинговая оценка, она осталась справочной; расчёт
  берёт `div_yield_by_expiry[expiry]`.
- **В базе хранится график выплат `div_schedule`, а не готовое q.** q
  зависит от сегодняшней даты и назавтра неверно, поэтому пересчитывается
  в `market_data.prime_cache` при каждом подъёме кэша.
- **Отменённый дивиденд ловится двумя независимыми проверками** —
  прогнозом Yahoo `info["dividendRate"]` и тишиной в истории выплат.
  Недоступный источник означает «не знаю», а не «отменили»: обнулять
  дивиденд по сетевой ошибке нельзя.
- **Паритет в `parity.py` считается по котировкам bid/ask, не по цене
  последней сделки.** Границы выхода за паритет зависят от нашего спота,
  а сам форвард — нет; отбраковывать форвард по этим границам нельзя,
  иначе при съехавшем споте пропадает ровно то число, которое этот сдвиг
  и показывает.
- **Согласие в сверке решается по форварду, а не по q.** q — ставка
  годовая, и на месячном сроке тот же сдвиг форварда даёт в двенадцать
  раз большее расхождение q, чем на годовом; фиксированный порог по q
  кричал бы впустую.
- **Новая колонка NOT NULL на заполненной таблице проходит только с
  `server_default`**, который сразу после добавления снимается
  `alter_column(server_default=None)`. Три миграции подряд спотыкались об
  это.
