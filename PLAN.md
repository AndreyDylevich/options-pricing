# План работы модуля — по шагам сценария пользователя

## Шаг 0. Пользователь открывает сайт

`GET /` → `app/main.py` отдаёт `app/static/index.html`.
Страница пустая, кроме выпадающего списка акций. `app.js` сразу дёргает шаг 1.

## Шаг 1. Загрузка списка акций

`GET /api/instruments` → `app/routers/instruments.py`

Список из 15-20 тикеров (AAPL, MSFT, NVDA, TSLA, SPY, SPX...). На первом
этапе — константа в `app/services/market_data.py`, на этапе 6 — таблица
`instruments` в PostgreSQL.

Ответ:
```json
[{"ticker": "AAPL", "name": "Apple Inc.", "exchange": "NASDAQ"},
 {"ticker": "MSFT", "name": "Microsoft Corp.", "exchange": "NASDAQ"}]
```

Фронт заполняет `<select>`.

## Шаг 2. Пользователь выбрал акцию → идём в yfinance

`GET /api/instruments/AAPL/market` → `app/services/market_data.py`

Здесь весь pandas. Тянем историю за год одним запросом:

```python
import numpy as np, yfinance as yf

t  = yf.Ticker("AAPL")
df = t.history(period="1y", interval="1d")
# DataFrame: индекс — даты, колонки Open High Low Close Volume Dividends
```

Из этого DataFrame считаем всё, что нужно моделям:

| Параметр | Как считается |
|---|---|
| `spot` (S) | `df["Close"].iloc[-1]` |
| `sigma_30d` | `np.log(df["Close"]).diff().tail(30).std() * np.sqrt(252)` |
| `sigma_90d` | то же на хвосте в 90 строк |
| `div_yield` (q) | сумма выплат за год к цене — справочно |
| `div_yield_by_expiry` | эффективное q под каждую экспирацию, по датам отсечек |
| `div_schedule` | предстоящие отсечки: объявленная из `t.calendar` + продолжение по ритму |
| `expirations` | `t.options` — кортеж доступных дат экспирации |

Безрисковая ставка — отдельным тикером, 13-недельные казначейские векселя США:

```python
r = yf.Ticker("^IRX").history(period="5d")["Close"].iloc[-1] / 100
```

Ответ фронту:
```json
{"ticker": "AAPL", "spot": 214.30, "currency": "USD",
 "sigma_30d": 0.284, "sigma_90d": 0.301, "div_yield": 0.0044,
 "risk_free_rate": 0.0412,
 "expirations": ["2026-09-18", "2026-10-16", "2026-12-18"],
 "as_of": "2026-08-14T14:32:00Z"}
```

Фронт подставляет эти числа в поля формы **как значения по умолчанию** —
пользователь может их переписать.

## Шаг 3. Пользователь заполняет параметры опциона

Поля на странице:

| Поле | Откуда берётся |
|---|---|
| Цена базового актива S | подставлена из шага 2, редактируется |
| Страйк K | вводит пользователь |
| Дата экспирации | выпадающий список из `expirations` |
| Тип: call / put | переключатель |
| Стиль: европейский / американский | переключатель |
| Волатильность σ | подставлена `sigma_30d`, редактируется |
| Ставка r | подставлена, редактируется |
| Дивидендная доходность q | подставлена под выбранную экспирацию, редактируется |
| Шагов дерева | 500 по умолчанию |
| Путей Монте-Карло | 100 000 по умолчанию |

Срок до экспирации T в годах пользователь не вводит — считает бэкенд из
даты: `(expiry - today).days / 365`.

## Шаг 4. Пользователь жмёт одну из трёх кнопок

Три кнопки: **Блэк-Шоулз**, **Биномиальное дерево**, **Монте-Карло**.
Каждая отправляет один и тот же запрос, отличается только поле `model`.

`POST /api/price` → `app/routers/pricing.py`

```json
{"model": "binomial", "ticker": "AAPL",
 "spot": 214.30, "strike": 220, "expiry": "2026-09-18",
 "option_type": "call", "exercise": "american",
 "sigma": 0.284, "rate": 0.0412, "div_yield": 0.0044,
 "steps": 500}
```

## Шаг 5. Бэкенд считает цену

`app/services/pricing_service.py`:
1. считает T из даты экспирации;
2. собирает `OptionParams`;
3. по полю `model` выбирает функцию из `app/pricing/`.

| `model` | Модуль | Что делает |
|---|---|---|
| `black_scholes` | `black_scholes.py` | формула БШМ, только европейский |
| `binomial` | `binomial.py` | дерево CRR, европейский и американский |
| `monte_carlo` | `monte_carlo.py` | GBM, антитетические переменные, + доверительный интервал |

## Шаг 6. Сразу после цены — греки

Отдельного запроса нет: греки считаются в том же вызове, иначе цена и
греки могут разъехаться по параметрам.

| Модель | delta, gamma, theta | vega, rho |
|---|---|---|
| Блэк-Шоулз | аналитические формулы | аналитические формулы |
| Дерево | снимаются с узлов дерева, без пересчёта | численно, bump-and-revalue |
| Монте-Карло | численно, на фиксированном seed | численно, на фиксированном seed |

Единицы: vega — на 1 п.п. волатильности, theta — на 1 день, rho — на
1 п.п. ставки.

## Шаг 7. Ответ и вывод на странице

```json
{"price": 8.42,
 "greeks": {"delta": 0.481, "gamma": 0.0182, "vega": 0.243,
            "theta": -0.061, "rho": 0.118},
 "meta": {"model": "binomial", "elapsed_ms": 87,
          "std_error": null, "ci95": null}}
```

Фронт рисует цену крупно, греки — пятью карточками. У Монте-Карло
дополнительно показывается доверительный интервал.

Расчёт пишется в таблицу `calculations` (этап 6). Наружу история не
отдаётся: её смотрят прямо в PostgreSQL, а записи старше трёх дней
удаляет фоновая задача — таблица растёт от каждого нажатия «Рассчитать»
и от каждого прогона тестов.

# Порядок сборки

| Этап | Что делаем | Что можно проверить |
|---|---|---|
Собираем в том же порядке, в каком идёт сценарий: каждый этап
заканчивается тем, что можно открыть в браузере и потыкать.

| Этап | Шаги сценария | Что делаем | Что видно в браузере |
|---|---|---|---|
| 1 | 0-1 | `GET /api/instruments` со списком-константой, `<select>` на странице | страница открывается, в списке акции |
| 2 | 2 | `market_data.py` на yfinance + pandas, `GET /api/instruments/{ticker}/market` | выбрал AAPL — под списком живые спот, σ, q, r, даты экспирации |
| 3 | 3 | форма параметров опциона, автоподстановка значений из шага 2 | форма заполняется сама, поля редактируются |
| 4 | 4-7 | `app/pricing/`: `models.py` + `black_scholes.py` + `numeric_greeks.py`, схемы, `POST /api/price`, кнопка и вывод. Тесты на БШ | **сквозной сценарий работает целиком**, одна кнопка |
| 5 | 4-6 | `binomial.py` (европейский и американский) и `monte_carlo.py` (+ доверительный интервал). Тесты на сходимость | три кнопки, цены сходятся между собой |
| 6 | 2, 7 | PostgreSQL: кэш рыночных данных, таблица `calculations` | данные переживают перезапуск, расчёты видны в базе |

Ключевая точка — этап 4: после него сценарий из шагов 0-7 отрабатывает
от начала до конца, дальше только добавляются модели и хранение.

Сами модели пишутся и прогоняются из консоли до того, как их подключат к
кнопке: `app/pricing/` не импортирует ничего, кроме numpy и scipy, и
отлаживается отдельно от браузера.

## Этап 12. Сверка входных данных с рынком

Все прочие проверки в проекте внутренние: дерево сходится к
Блэку-Шоулзу, численные греки совпадают с аналитическими, цена лежит в
границах отсутствия арбитража. Они отвечают на вопрос «правильно ли
посчитана формула» и молчат о том, верны ли подставленные в неё числа.

Паритет колла и пута отвечает на второй вопрос. Для пары на одном
страйке рынок держит `C - P = S*exp(-qT) - K*exp(-rT)`: слева чистые
рыночные цены, справа наши спот, ставка и дивидендная доходность.
Волатильность в равенство не входит, поэтому проверка не зависит от
того, как мы её оцениваем, и не вырождается в тавтологию — в отличие от
сравнения нашей цены с рыночной через подразумеваемую волатильность,
которая из этой же цены и получена.

| что | где |
|---|---|
| математика паритета, границы, форвард | `app/pricing/parity.py` |
| сборка пар из цепочки, вердикт | `pricing_service.parity_report` |
| `GET /api/instruments/{ticker}/parity` | `routers/instruments.py` |
| карточка «Сверка с рынком» | `static/index.html`, `app.js` |

Отсюда же приходит второе, независимое q: из рыночного форварда, а не из
дат отсечек. Сходятся две оценки — значит с дивидендами всё в порядке.
В него заодно входит стоимость заимствования бумаги, которую по истории
выплат не увидеть никак.

Оговорка: равенство доказано для европейских опционов, а на американские
акции торгуются американские. Для них верно только неравенство
`S*exp(-qT) - K <= C - P <= S - K*exp(-rT)` — оно проверяется отдельно.
Само равенство остаётся хорошим приближением у денег, где премия за
досрочное исполнение почти нулевая; поэтому итоговый форвард собирается
по пяти страйкам с наименьшим |C - P|.

# Что появится позже, когда основное заработает

- **Implied volatility** — `t.option_chain(date)` отдаёт DataFrame с
  рыночными ценами опционов и страйками. Решаем обратную задачу: какая σ
  даёт рыночную цену. Это позволяет сверять наши модели с реальным рынком.
- **Улыбка волатильности** — та же процедура по всем страйкам цепочки,
  накопленные значения из таблицы `calculations`, график.
- **График сходимости** — как цена дерева приближается к Блэку-Шоулзу с
  ростом числа шагов, как падает ошибка Монте-Карло с ростом числа путей.
